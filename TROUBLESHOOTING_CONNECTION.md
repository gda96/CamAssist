# Диагностика проблем подключения к ESP32-C3

## Исправления в версии 1.28

### 1. Увеличены таймауты подключения
- **Было:** 5 секунд
- **Стало:** 10 секунд
- **Причина:** ESP32-C3 может быть медленнее при обработке HTTP запросов

### 2. Улучшена обработка ошибок
- Добавлены понятные сообщения об ошибках для пользователя
- Разные сообщения для разных типов ошибок:
  - Таймаут подключения
  - Не удалось найти устройство (DNS ошибка)
  - Устройство недоступно (Connection refused)

### 3. Улучшен UDP клиент
- Добавлен таймаут 5 секунд для предотвращения блокировки
- Улучшена обработка ошибок
- Добавлено логирование IP адреса отправителя

### 4. Улучшена проверка SSID
- Добавлена проверка частичного совпадения имени сети
- Улучшена обработка исключений при проверке WiFi

## Возможные причины проблем с подключением

### 1. Устройство в AP режиме (точка доступа)
**Симптомы:**
- Приложение не может подключиться
- Ошибка "Не удалось найти устройство"

**Решение:**
1. Убедитесь, что Android устройство подключено к сети `Camera_Heater_AP`
2. Пароль по умолчанию: `12345678`
3. После подключения приложение должно автоматически найти устройство по IP `192.168.4.1`

### 2. Устройство в STA режиме (подключено к домашней сети)
**Симптомы:**
- Приложение не может подключиться
- Ошибка "Таймаут подключения"

**Решение:**
1. Убедитесь, что Android устройство подключено к той же WiFi сети, что и ESP32
2. Проверьте IP адрес ESP32 в настройках роутера или через веб-интерфейс устройства
3. Приложение должно автоматически получить IP через UDP broadcast
4. Если UDP не работает, вручную введите IP адрес в настройках WiFi приложения

### 3. Веб-сервер ESP32 не запущен
**Симптомы:**
- Ошибка "Устройство недоступно" или "Connection refused"

**Решение:**
1. Перезагрузите ESP32 устройство
2. Проверьте Serial Monitor - должен быть вывод "✅ Веб-сервер запущен"
3. Попробуйте открыть веб-интерфейс в браузере по адресу `http://192.168.4.1` (AP режим) или IP устройства (STA режим)

### 4. Проблемы с сетью
**Симптомы:**
- Периодические разрывы соединения
- Медленная работа приложения

**Решение:**
1. Проверьте качество WiFi сигнала
2. Убедитесь, что нет помех от других устройств
3. Попробуйте перезапустить WiFi на ESP32 через приложение (кнопка "Перезагрузить")

### 5. Проблемы с разрешениями Android
**Симптомы:**
- Приложение не может определить сеть
- UDP не работает

**Решение:**
1. Убедитесь, что приложение имеет все необходимые разрешения:
   - INTERNET
   - ACCESS_NETWORK_STATE
   - ACCESS_WIFI_STATE
   - CHANGE_WIFI_STATE
2. Проверьте настройки безопасности сети в Android (cleartext traffic должен быть разрешен)

## Диагностика через логи

### Android Studio Logcat
Фильтры для поиска:
- `UdpClient` - логи UDP клиента
- `DeviceViewModel` - логи ViewModel
- `ApiClient` - логи HTTP запросов
- `NetworkUtils` - логи определения IP адреса

### Serial Monitor ESP32
Проверьте вывод:
- `✅ Веб-сервер запущен` - сервер работает
- `📡 Ожидание запросов...` - сервер готов принимать запросы
- `🔄 Запрос управления` - получен запрос от приложения

## Рекомендации

1. **Всегда начинайте с AP режима** - это самый надежный способ подключения
2. **Используйте UDP для автоматического обнаружения** - приложение автоматически получит IP адрес
3. **Проверяйте логи** - они помогут понять, где именно происходит проблема
4. **Перезагружайте устройство** - если проблемы продолжаются, перезагрузите ESP32
