# Изменения в коде ESP32-C3 Camera Heater

## Версия 7.2 - Добавлен mutex для WiFi + оптимизация памяти

### Выполненные изменения:

#### 1. Добавлен mutex для синхронизации WiFi-операций (race condition fix)

**Проблема:** Одновременный доступ к переменным `wifiSTAEnabled`, `forceAPMode`, `wifiConnected` из разных частей кода мог приводить к непредсказуемому поведению.

**Решение:**
- Добавлен `SemaphoreHandle_t wifiMutex` (строка 20)
- Инициализация в `setup()`: `wifiMutex = xSemaphoreCreateMutex()`
- Защищены критические секции в функциях:
  - `checkAndRestoreWiFi()`
  - `resetWiFiConnection()`
  - `connectToWiFiNetwork()`
  - `handleUpdateWifi()`

**Пример использования:**
```cpp
if (xSemaphoreTake(wifiMutex, portMAX_DELAY) == pdTRUE) {
    forceAPMode = true;
    wifiSTAEnabled = false;
    xSemaphoreGive(wifiMutex);
}
```

#### 2. Оптимизация использования памяти

**Изменения:**
- Заменен `DynamicJsonDocument` на `StaticJsonDocument<4096>` для `scanResult` (строка 43)
  - Преимущество: выделение памяти на стеке вместо кучи
  - Избегается фрагментация heap-памяти
  
- Добавлены комментарии о корректном использовании `String` (строка 22)
  - String используется осторожно для WiFi параметров
  - Избегается частое создание/удаление String объектов

- Использование `send_P()` для отправки HTML из PROGMEM (строка 1707)
  - `server.send_P(200, "text/html; charset=utf-8", htmlPage);`
  - HTML хранится во flash-памяти, не занимая RAM

#### 3. Извлечен HTML в отдельный файл

**Файл:** `interface.html`
- Полный веб-интерфейс с CSS и JavaScript
- Упрощает разработку и отладку дизайна
- Можно тестировать локально в браузере
- 66502 байта

### Структура файлов:

1. **sketch_good_cam_dat_knop.ino** (115046 байт)
   - Основной код Arduino для ESP32-C3
   - Управление обогревателем, датчиками, WiFi
   - Добавлена синхронизация и оптимизация памяти

2. **interface.html** (66502 байт)
   - Веб-интерфейс (HTML + CSS + JavaScript)
   - Адаптивный дизайн для мобильных и десктопов
   - Управление калибровкой и WiFi настройками

### Преимущества изменений:

1. **Стабильность:**
   - Устранены race conditions в WiFi-операциях
   - Предсказуемое поведение при конкурентном доступе

2. **Память:**
   - Меньше фрагментации heap
   - Более эффективное использование RAM
   - Предсказуемое потребление памяти

3. **Разработка:**
   - HTML отделен от кода Arduino
   - Упрощена отладка интерфейса
   - Легче вносить изменения в дизайн

После загрузки кода необходимо проверить:
1. Корректную инициализацию мьютекса (лог в Serial)
2. Отсутствие утечек памяти (команда `ESP.getFreeHeap()`)
3. Стабильность WiFi-подключений
4. Корректную работу веб-интерфейса

### Использование памяти (примерные значения):

- Flash: ~300 KB (код + HTML)
- SRAM: ~40-50 KB (переменные, стек, heap)
- Heap доступно после загрузки: ~200+ KB

ESP32-C3 имеет 400 KB SRAM, что достаточно для данного приложения.
