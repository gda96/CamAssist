# Отчет о проверке работы с EEPROM/Preferences

**Дата проверки:** 08.12.2025  
**Версия скетча:** 7.8

## Обзор

В скетче используется библиотека `Preferences` (обертка над EEPROM в ESP32) для хранения:
- Калибровочных параметров (температура, влажность, коррекции)
- Настроек отображения (скрытие информации о подключении)
- Настроек WiFi (SSID, пароли, режимы)

## ✅ Положительные моменты

1. **Правильное использование режимов:**
   - `true` (read-only) для загрузки данных
   - `false` (read-write) для сохранения данных

2. **Проверка ошибок:** Большинство мест проверяют результат `begin()`

3. **Правильное закрытие:** Все `begin()` имеют соответствующий `end()`

## ⚠️ Найденные проблемы

### 1. КРИТИЧНО: Отсутствие сообщения об ошибке в saveSettings()

**Место:** Строка 2023-2025

**Проблема:**
```cpp
void saveSettings() {
  if (!preferences.begin("calibration", false)) {
    Serial.println("❌ Ошибка открытия Preferences для сохранения");
    return;  // ✅ Сообщение есть, но это нормально
  }
```

**Статус:** ✅ На самом деле сообщение есть, это не проблема.

---

### 2. ПРОБЛЕМА: Отсутствие проверки успешности операций put

**Место:** Все функции сохранения

**Проблема:**
Методы `putFloat()`, `putString()`, `putBool()` не проверяются на успешность выполнения.

**Пример:**
```cpp
preferences.putFloat("tempThreshold", calParams.tempThreshold);
preferences.putString("staSSID", staSSID);
preferences.putBool("staEnabled", wifiSTAEnabled);
```

**Риск:** Если операция записи не удалась (например, из-за нехватки места в EEPROM), ошибка не будет обнаружена.

**Рекомендация:**
В ESP32 Preferences методы `put*()` возвращают `size_t` (количество записанных байт). Можно добавить проверку:
```cpp
size_t written = preferences.putFloat("tempThreshold", calParams.tempThreshold);
if (written == 0) {
  Serial.println("⚠️ Ошибка записи в Preferences");
}
```

**Приоритет:** 🟡 Средний (ESP32 обычно имеет достаточно места в NVS)

---

### 3. ПРОБЛЕМА: Потенциальная проблема с длинными строками

**Место:** Строки 2064-2067, 2601-2604

**Проблема:**
Строки SSID и пароли сохраняются без проверки длины.

**Риск:** 
- SSID может быть до 32 символов (безопасно)
- Пароль WiFi может быть до 63 символов (безопасно)
- Но если в будущем будут использоваться более длинные строки, может возникнуть проблема

**Рекомендация:**
Добавить проверку длины перед сохранением:
```cpp
if (staSSID.length() > 32) {
  Serial.println("⚠️ SSID слишком длинный, обрезаем");
  staSSID = staSSID.substring(0, 32);
}
```

**Приоритет:** 🟢 Низкий (текущие ограничения WiFi достаточны)

---

### 4. ПРОБЛЕМА: Отсутствие валидации загруженных данных

**Место:** Строки 1996-1999, 2600-2604

**Проблема:**
Загруженные из Preferences данные не проверяются на валидность.

**Пример:**
```cpp
calParams.tempThreshold = preferences.getFloat("tempThreshold", factoryCalibration.tempThreshold);
```

**Риск:** Если в EEPROM были записаны некорректные данные (например, из-за сбоя), они будут использованы без проверки.

**Рекомендация:**
Добавить валидацию после загрузки:
```cpp
calParams.tempThreshold = preferences.getFloat("tempThreshold", factoryCalibration.tempThreshold);
if (calParams.tempThreshold < -50.0 || calParams.tempThreshold > 50.0) {
  Serial.println("⚠️ Некорректное значение tempThreshold, используем заводское");
  calParams.tempThreshold = factoryCalibration.tempThreshold;
}
```

**Приоритет:** 🟡 Средний

---

### 5. ПРОБЛЕМА: Потенциальная проблема с одновременным доступом

**Место:** Все функции работы с Preferences

**Проблема:**
Хотя ESP32-C3 одноядерный, теоретически возможна ситуация, когда одна функция пытается открыть Preferences, а другая еще не закрыла.

**Риск:** Низкий, так как ESP32-C3 одноядерный и нет реальной многопоточности, но стоит учитывать при отладке.

**Рекомендация:**
Добавить защиту от повторного открытия:
```cpp
static bool preferencesOpen = false;

void saveSettings() {
  if (preferencesOpen) {
    Serial.println("⚠️ Preferences уже открыт, закрываем перед повторным открытием");
    preferences.end();
    preferencesOpen = false;
  }
  
  if (!preferences.begin("calibration", false)) {
    Serial.println("❌ Ошибка открытия Preferences");
    return;
  }
  preferencesOpen = true;
  
  // ... операции ...
  
  preferences.end();
  preferencesOpen = false;
}
```

**Приоритет:** 🟢 Низкий (текущая архитектура не требует этого)

---

### 6. ПРОБЛЕМА: Отсутствие проверки на переполнение EEPROM

**Место:** Все функции сохранения

**Проблема:**
Нет проверки, достаточно ли места в NVS (Non-Volatile Storage) для записи.

**Риск:** Если NVS переполнен, записи могут не выполняться.

**Рекомендация:**
ESP32 Preferences автоматически управляет NVS, но можно добавить проверку:
```cpp
// Проверка доступного места (если доступно через API)
size_t freeEntries = preferences.freeEntries();
if (freeEntries < 5) {
  Serial.println("⚠️ Мало свободного места в NVS");
}
```

**Приоритет:** 🟢 Низкий (ESP32 имеет достаточно места в NVS для текущих данных)
